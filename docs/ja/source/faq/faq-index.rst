FAQ
****

超伝導・Eliashberg方程式の利用
==========================================

超伝導へのスピン・電荷の寄与を切り分けたい
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q. 超伝導解析において、電荷とスピンの影響を切り分けて評価できますか？**

可能です。動的 Eliashberg ソルバ（``[eliashberg] frequency = "dynamic"``\ 、
FLEX の感受率を読み込むモード）では、ペアリング頂点はスピン
（:math:`\chi_{\mathrm s}`\ ）・電荷（:math:`\chi_{\mathrm c}`\ ）感受率から構成され、
両チャネルについて\ **線形**\ です。したがって ``[eliashberg]``\ セクションで
一方のチャネルを 0 にすることで、各チャネルがペアリング固有値 :math:`\lambda`
に与える効果を比較できます。

- ``zero_chi_c = true``\ とすると、スピンゆらぎ項＋裸の項が残ります。
- ``zero_chi_s = true``\ とすると、電荷ゆらぎ項＋裸の項が残ります。

全チャネルを含む計算（full）と、一方のチャネルをゼロにした2通りの計算を行い、
得られた :math:`\lambda`\ を比較すれば、
どちらのゆらぎチャネルの効果が相対的に強いかを診断する目安になります。
いずれのフラグも既定は ``false``\ なので通常の計算には影響せず、
``pairing_type`` が ``"singlet"``\ でも ``"triplet"``\ でも使えます。

.. note::

   瞬間的な（裸の）相互作用項は常に保持され、主要固有値はペアリング頂点に対して
   線形ではないため、固有値は加算されません（一般に
   :math:`\lambda_{\mathrm s} + \lambda_{\mathrm c} \neq
   \lambda_{\mathrm{full}}`\ ）。ここで :math:`\lambda_{\mathrm s}`\ と
   :math:`\lambda_{\mathrm c}`\ は、それぞれ ``zero_chi_c = true``
   （スピンゆらぎ項＋裸の項）と ``zero_chi_s = true``
   （電荷ゆらぎ項＋裸の項）による計算の固有値です。裸の項は両方に含まれるため、
   単純に加算すると二重に数えることにもなります。この分解は2つのチャネルの
   相対的な強さの比較に用い、厳密な加法的分割としては扱わないでください。

頂点の式や詳細は :ref:`sc_channel_decomposition`\ を参照してください。

:math:`\lambda`\ が 1 に達しないときの :math:`T_c`\ の見積もり方
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q. 主要固有値が 1 に達しません。**\ :math:`T_c`\ **をどう見積もればよいですか？**

:math:`\lambda = 1`\ が\ :math:`T_c`\ を与えるのは、温度に対して連続的に
追跡した1つの物理的ブランチの固有値としての\ :math:`\lambda`\ が 1 を
横切るときです。ある温度で\ :math:`\lambda < 1`\ であることは、その温度で
常磁性状態が安定であることを示すにすぎず、:math:`T_c`\ にどれだけ近いかは
分かりません。横切る点を見つけるには、より低い温度で計算する必要があります。
``hwave_tsweep``\ を使えば降温ラダーを自動化でき、各段で最終的に保存された
自己エネルギー（動的ソルバの場合は主要固有ベクトルも）を次の段に引き継ぎ
ます（:ref:`sc_tsweep`\ を参照）。ただし、収束していない段の自己エネルギー
でもそのまま次の段のシードに使われるため、サマリーの ``flex_converged``\ 列
を確認してください。FLEX+Eliashberg による\ :math:`T_c`\ はあくまで半定量的
な値である点にも注意してください（:ref:`faq_flex_tc`\ ）。パラメータを
振ったときの\ :math:`\lambda(T)`\ や\ :math:`\lambda(P)`\ の位置・形状を
比較する方が、追跡したブランチが 1 を横切る絶対値そのものを読むよりも
頑健です。

FLEXが低温で収束しない（コールドスタートの失敗）
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q. 高温では収束するのに、低温の FLEX 計算だけ収束しません。どうすればよい
ですか？**

:math:`\Sigma = 0`\ から始めるコールドスタートは、相関が強くなるにつれて
SCF の不動点が\ :math:`\Sigma = 0`\ から遠ざかるため、低温でいきなり実行すると
収束しないことがよくあります。代わりに、収束しやすい高温から始めて温度を
少しずつ下げ、各温度の最終的な自己エネルギーを次の計算のウォームスタート
として渡してください（``[file.input] sigma_init``\ 、:ref:`flex_sigma_init`\ を
参照）。``hwave_tsweep``\ はこのラダー全体を自動化し、各段の収束状況も記録
するので、あるウォームスタートが実際に収束した段から来たものかどうかを
確認できます（:ref:`sc_tsweep`\ ）。

温度を変えると最大固有値やギャップ対称性が飛び移る
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q. 温度を少しずつ変えていくと、主要固有値のギャップ対称性が突然別のものに
切り替わります。計算がおかしいのでしょうか？**

必ずしもそうとは限りません。動的（周波数依存）Eliashberg カーネルは
非エルミートであり、2つの実固有値が衝突して複素共役対に分裂する
「例外点」を持つことがあります。そのため、FLEX の自己エネルギーが滑らかに
変化していても、隣り合う温度の間で「主要」ブランチが不連続に飛ぶことが
あります。``[eliashberg] seed_eigenvector``\ に隣接する計算の
``gap_dynamic.npz``\ を指定すると、1つの物理的なブランチ（例えば d 波
モード）を温度掃引全体にわたって連続的に追跡しやすくなります。具体的には、
固有値ソルバが実際に\ **返した**\ 固有対（``num_eigenvalues``\ 、および
シフトインバートを使う場合は ``sigma_shift``\ で決まる範囲）の中から、
単に代数的に最大の固有値ではなく、指定した固有ベクトルと最も重なりの
大きい固有対を選びます。物理的なブランチがそもそも返された固有対の中に
なければ、``num_eigenvalues``\ を増やすか ``sigma_shift``\ をその近傍に
移すことで範囲内に入れる必要があります。仕組みの全体像は
:ref:`sc_seed_eigenvector`\ を参照してください。

得られたギャップ対称性の確認方法（``match``\ 列）
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q.** ``init_gap`` **である対称性を狙ってシードしましたが、実際にその対称性
に収束したのか確信が持てません。どう確認すればよいですか？**

``init_gap``\ （静的ソルバ）は自己無撞着反復のシードにすぎず、報告される
結果は要求したチャネルの\ **パリティ**\ （singlet なら偶、triplet なら奇）に
属する主要固有対であって、シードした対称性そのものとは限りません。また
固有値解析には、その意味では物理的でない反対パリティの解も含まれます。
``eigenvalue.dat``\ の末尾にある ``match``\ 列は厳密な判定ではなく優勢さの
判定です。固有ベクトルを要求したチャネルパリティの成分に射影したときに
ノルムの 90% 以上が残る場合に ``1``\ （物理的）、そうでない場合に ``0``\
（擬似的）になります。この基準を満たす固有対が1つも計算されなかった場合、
ソルバは警告を出したうえで、一致しなかった最大固有対をそのまま報告に
フォールバックします。その場合は ``num_eigenvalues``\ を増やすか
``pairing_type``\ を確認してください。実際にどの対称性が得られたかは、
報告されたギャップ関数そのもの（``gap.dat``\ やチュートリアルの図）を確認して
判断してください。ファイル形式と、反対パリティの解がそもそも現れる理由に
ついては :ref:`sc_eigenvalue_dat`\ を参照してください。

:math:`\lambda(T)`\ が非単調 -- 物理的な現象か？
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q. 一つのペアリングチャネルについて、温度を下げていくと** :math:`\lambda`
**が一旦下がってからまた上がります。これは実際の物理効果でしょうか？**

それを物理的だと結論する前に、まずよくある非物理的な原因を除外してください。
連続的に追跡された1つのペアリングブランチに対しては、:math:`\lambda`\ は
:math:`T \to 0`\ で増加すると期待されるため、説明のつかないくぼみが出たら
次を確認する価値があります。その段がウォームスタートされ収束した段からの
ものではなく、コールドスタートまたは FLEX の自己エネルギーが十分収束して
いない段である可能性（``hwave_tsweep``\ サマリーの ``flex_converged``\ 列
を確認、:ref:`flex_sigma_init`\ ）、「主要」固有対が段の間で対称性を
静かに変えてしまう例外点でのブランチの切り替わり（:ref:`sc_seed_eigenvector`\
）、そして IR 経路を使っている場合は ``ir_wmax``\ や FLEX ``Nmat``\ の
分解能不足（:ref:`sc_dynamic_ir`\ ）です。温度ラダー全体
（:ref:`sc_tsweep`\ ）を1つずつ確認し、``seed_eigenvector``\ を使って
1つの物理的ブランチを追跡できていることを確かめたうえで、そのくぼみを
本物の非単調な効果として扱ってください。

動的モードの前提条件と\ ``ir_wmax``\ の選び方
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q.** ``frequency = "dynamic"`` **を使う前に何が必要ですか。また**
``ir_wmax`` **はどう選べばよいですか？**

``frequency = "dynamic"``\ には、事前に実行した FLEX 計算
（``chi0q_mode = "flex"``\ ）でしか得られない周波数分解された入力が必要です。
必要なファイルと ``Nmat``\ の整合性チェックについては
:ref:`sc_dynamic_frequency`\ を参照してください。IR 経路
（``matsubara_basis = "ir"``\ ）を使う場合はさらに、オプションパッケージの
`sparse-ir <https://sparse-ir.readthedocs.io>`_ が必要です。``ir_wmax``\ は、
それを大きくしても\ :math:`\lambda`\ が変わらなくなる程度に十分大きく
選んでください（より大きな値や自動推定値と比較して確認します）。逆に
大きくしすぎると、IR ローダーが分離しようとする
delta(:math:`\tau`\ )由来の定数項の推定がかえって不安定になることが
あります。その場合の対処法は、自動推定される ``ir_wmax``\ （またはバンド幅
と最大相互作用の和の 3 倍程度の値）を使う、FLEX の ``Nmat``\ を大きくする、
真に静的な成分を保持するよう ``ir_keep_static_chi = true``\ を設定する、
あるいは ``matsubara_basis = "uniform"``\ に戻すことです。自動推定や
分離の診断、測定された固有値の感度については :ref:`sc_dynamic_ir`\ を
参照してください。

大きな\ ``Nmat``\ でのGPUメモリ不足
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q.** ``gpu = true`` **で動的 Eliashberg 計算を実行すると、大きな**
``Nmat`` **でメモリ不足エラーが出ます。どうすればよいですか？**

デバイス上に常駐する2つの大きなテンソル（ペアバブルとペアリング頂点）は
:math:`N_{\mathrm{orb}}^4 N_k N_{\mathrm{mat}}`\ に比例するため、GPU メモリ
使用量は ``Nmat``\ （およびkメッシュサイズや軌道数）に直接比例して増えます。
``Nmat``\ や ``CellShape``\ を小さくするか、同じデバイス上で同時に走らせる
計算数を減らしてください。大きなメモリ確保を行う前に、ソルバーは常駐
テンソルのサイズを必ずログに出力します。その見積もりがデバイスの空き
メモリを超える場合に\ **限り**\ 、必要量と空き容量を示す警告が追加で
出力されます（あくまで事前警告であり、実際の確保に失敗すれば CuPy 自身が
明確な out-of-memory エラーを出します）。実行が黙って収まると仮定せず、
この警告が出るかどうかに注意してください。メモリ量の式や速度・メモリの
目安については :ref:`sc_dynamic_gpu`\ を参照してください。

2軌道系の\ ``chi_convention``\ （``kuroki``\ 対\ ``myo``\ ）
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q. ファイルの配列形状は想定通りなのに、2軌道系の FLEX+Eliashberg の結果が
おかしく見えます。何を確認すればよいですか？**

FLEX の感受率ファイルには ``chi_convention``\ タグ（reduced スキームなら
``"kuroki"``\ 、general フルベルテックススキームなら ``"myo"``\ ）が付与
されており、Eliashberg のローダーはこれを使って格納された軌道配置を
解釈します。ローダーは、何かおかしいと判定できる場合には推測せずに
エラーにします。``chi_s``\ ・``chi_c``\ のペアに異なるタグが付いている場合、
未知のタグの場合、あるいは（配列形状から規約が一意に決まる
:math:`N_{\mathrm{orb}} \neq 2`\ の場合に限り）タグが形状と矛盾する場合は、
すべて誤読せずに明示的なエラーを送出します。この方法で検出できない唯一の
ケースが\ :math:`N_{\mathrm{orb}} = 2`\ です。この場合、reduced のスピン
軌道次元と general の軌道対次元がどちらも 4 で一致してしまうため、配列の\
**形状だけでは区別できません**\ 。もしそのファイル自体は内部的に矛盾が
ないものの、実際の中身とは違う規約タグが付いている場合（例えば
kuroki レイアウトのファイルに誤って ``"myo"``\ タグが付いている場合）、
ローダーにはそれを検出する手立てがなく、誤ったペアリング頂点を静かに
構築してしまいます。詳しい説明と、
このタグが防いでいる過去の誤ラベル付けについては
:ref:`sc_dynamic_frequency`\ を参照してください。


FLEX近似
==========================================

FLEXの適用範囲
^^^^^^^^^^^^^^^^

**Q. FLEX にはどのような限界がありますか。どのような場合に信頼すべきでは
ありませんか？**

FLEX は RPA の粒子・空孔バブルとラダー級数から構成される、弱結合から
中間結合領域向けの保存則を満たす近似であり、Aslamazov-Larkin /
Maki-Thompson 頂点補正を含みません。また Mott 絶縁体状態を記述する
ことはできません。ここで解いている常磁性 FLEX は、磁気的・電荷的な
秩序相にも入ることができません。そのため、そのような不安定性の近傍
（感受率が大きくなる領域）で得られた大きな感受率やペアリング固有値は、
確定的な予言ではなく信頼できないものとして扱うべきであり、そこから
得られる転移温度もよくても半定量的なものです（:ref:`faq_flex_tc`\ ）。
密度‐密度（``reduced``\ ）とフルベルテックス（``general``\ ）の区別を
含む正確な適用範囲については :ref:`flex_scope`\ を参照してください。

不安定点近傍でFLEXが発散・収束しない
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q. 磁気的・電荷的な不安定性に近づくと、FLEX が収束しなくなったり
（あるいは感受率が発散したり）します。何が起きているのですか？**

磁気的な不安定性に近づくと、Stoner 因子（RPA で足し上げた相互作用と
:math:`\chi_0`\ の積）が 1 に近づき、それに伴って RPA 型の分母
（1 − Stoner 因子）が\ **0 に近づきます**\ （1 に近づくのではありません）。
そのため\ :math:`\chi`\ が大きくなり、自己無撞着ループが収束しにくく
なります。この領域には、ウォームスタートの温度ラダー
（:ref:`flex_sigma_init`\ 、:ref:`sc_tsweep`\ ）を使って緩やかに近づき、
混合もより穏やかにしてください。具体的な ``Mix``\ ・``mixing_scheme``\ の
指針は :ref:`flex_tips`\ と :ref:`flex_params`\ を参照してください。
その不安定性が物理的なもの
（本物の磁気秩序・電荷秩序）である場合、FLEX 自体は秩序相・絶縁相には
入れないことに注意してください。そこで得られる大きな感受率やペアリング
固有値は、近似が限界に近づいているしるしであって、その領域での超伝導を
信頼できる形で予言しているわけではありません。

.. _faq_flex_tc:

FLEXから得られる :math:`T_c`\ の読み方
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q. FLEX+Eliashberg 計算から具体的な** :math:`T_c` **の値が得られました。
どの程度信頼してよいでしょうか？**

半定量的な値として扱ってください。定量的なものではありません。絶対的な
:math:`T_c`\ は相互作用の強さにほぼ指数的に依存するため、相互作用の
較正の仕方にも近似そのもの（:ref:`flex_scope`\ ）にも敏感です。単一の
計算から得られる\ :math:`T_c`\ の絶対値に頼るのではなく、パラメータを
振ったときの\ :math:`\lambda(P, T)`\ の位置・形状といった傾向を比較して
ください。

FLEX収束のための\ ``Nmat``\ ・混合・``IterationMax``\ の選び方
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q. FLEX をきちんと収束させるには** ``Nmat``\ **、** ``mixing_scheme``\ **、**
``IterationMax`` **をどう設定すればよいですか？**

``Nmat``\ は偶数で、かつ対象の温度で低周波構造を解像できるだけの十分な
数の松原周波数の和を取れる大きさが必要です（目安として
:math:`N_{\mathrm{mat}} \gtrsim 10/T`\ 、:ref:`flex_tips`\ を参照）。
Anderson 混合（``mixing_scheme = "anderson"``\ ）は、控えめな ``Mix``\ と
ウォームスタートを組み合わせると、低温での自己無撞着計算を通常の線形混合
よりずっと少ない反復回数で収束させられることが多いので、``IterationMax``\ を
増やすのはまずこちらを試してからにしてください。``IterationMax``\ ・
``Mix``\ ・``EPS``\ ・``mixing_scheme``\ ・``anderson_depth``\ の全パラメータ
表は :ref:`flex_params`\ を参照してください。

``calc_scheme = "auto"``\ が混成模型・FLEX計算を\ ``general``\ に昇格させる
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**Q. 入力を変えていないのに、アップデート後に計算が明らかに遅くなり、
出力配列も大きくなりました。なぜですか？**

バージョン 2.0 以降、``calc_scheme = "auto"``\ （既定値）は、常に安価な
``reduced``\ を優先するのではなく、宣言された入力に対して\ **厳密**\ になる
スキームを選ぶようになりました。RPA では、宣言されたすべての相互作用が
密度型のみであるか、一体ハミルトニアンが軌道フレーバーを保存する場合に
限って ``reduced``\ が維持されます。したがって ``CoulombInter``\ ・
``Hund``\ ・``Ising``\ を宣言した混成のある多軌道模型は ``general``\ に
昇格します。FLEX では、混成の有無にかかわらず、これらの相互作用（または
集約された ``Coulomb``\ 相互作用）のいずれかを宣言した\ **すべて**\ の
計算が無条件に ``general``\ に昇格します。これは自己無撞着ループでは
RPA 専用の厳密性の議論が使えないためです（:ref:`flex_scope`\ を参照）。
``general``\ は 6 階の ``chiq``\ を使うためコストが増加します（メモリ・
計算量が\ :math:`(\mathbf{q},\omega)`\ あたり\ :math:`O(N_d^2)/O(N_d^3)`\ から
:math:`O(N_d^4)/O(N_d^6)`\ に増えます）。2.0 より前の挙動をあえて維持したい
場合（その入力に対しては近似になるという警告が一度だけ表示されます）は
``calc_scheme = "reduced"``\ を明示してください。6 階配列から旧来の4軸
