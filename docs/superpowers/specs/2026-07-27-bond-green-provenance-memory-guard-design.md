# Bond Green Provenance and Memory Guard Design

## Context

PR #82 adds the opt-in static `bond_channels` Eliashberg path and permits an
external H-wave Green function through `[eliashberg] bond_green`. The current
loader checks only the array rank, total momentum-point count, orbital count,
and Matsubara-axis length. It does not verify the temperature that defines the
Matsubara frequencies or the momentum-grid shape/order. The resource preflight
also omits the dense matrices allocated by the default Hermiticity
precondition check.

These gaps can respectively produce plausible but scientifically invalid
eigenvalues and allow a run to exceed `bond_memory_cap_gb` after passing the
preflight.

## Goals

1. Refuse a `bond_green` file whose temperature differs from the Eliashberg
   run.
2. Refuse a `bond_green` file whose H-wave producer-supplied momentum-grid
   shape/order labels differ from the Eliashberg run, even when the total
   number of points is equal.
3. Make newly written FLEX Green files self-describing for these checks.
4. Make `bond_memory_cap_gb` cover the dense Hermiticity-check workspace.
5. Preserve all non-bond numerical arrays and loader behaviour. The FLEX
   `green.npz` key set intentionally gains additive provenance metadata.

## Non-goals

- Validating that the external Green function used exactly the same
  interaction strengths, filling, chemical potential, or convergence
  algorithm as the current run.
- Validating physical lattice-basis identity or orbital labels/model identity;
  schema v1 validates tensor conventions and counts only.
- Supporting arbitrary third-party Green-function layouts.
- Adding a permissive "trust me" switch for metadata-free `bond_green` files.
- Changing the bond-channel equations or eigensolver selection.

## Input Contract

The `bond_green` path is new in PR #82 and is not yet a released compatibility
surface. It will therefore use a strict contract.

An accepted file must contain:

- `green_schema_version`, the scalar integer `1`;
- `green`, in FLEX layout
  `(nblock=1, nfreq, nvol=Nx*Ny*Nz, norb, norb)`, whose momentum axis is
  labelled by `wavevector_index`;
- a scalar temperature, using a canonical `temperature` key in newly written
  files, with the existing fixture key `T` accepted as a compatibility alias;
- `cell_shape`, a length-three positive-integer array equal to `(Nx, Ny, Nz)`;
  shorter 1-D/2-D forms fail as a metadata-shape error rather than being padded;
- `wavevector_index`, an integer array of shape `(Nx*Ny*Nz, 3)`.

Temperature is expressed in the same H-wave energy units as `[mode.param] T`.
It must be a zero-dimensional little-endian float64 array (not a one-element vector)
containing a finite positive value, and satisfy
`np.isclose(T_file, T_run, rtol=1e-6, atol=1e-12)`. If both `temperature` and
the compatibility alias `T` exist, both are validated and all three
comparisons must pass: canonical-to-run, alias-to-run, and
canonical-to-alias. `temperature` is canonical. Boolean, integer, complex,
object, string, structured, and datetime dtypes are rejected.
Each comparison uses the symmetric rule
`abs(a-b) <= 1e-12 + 1e-6*max(abs(a), abs(b))`.
When both keys exist and fail pairwise comparison, the error reports
`temperature`, `T`, and expected `T_run`. Validation precedence is
canonical-to-run, alias-to-run, then canonical-to-alias. The canonical value
is retained only for diagnostics;
temperature does not otherwise flow from the file into the calculation.
The 1-ppm relative tolerance accommodates decimal configuration
serialization; the absolute term handles values near zero. A within-tolerance
canonical/alias difference is accepted without warning.

Ordering labels are validated, not inferred from volume.
`wavevector_index` must equal
the authoritative H-wave table generated by the existing `_klist` convention:
the nested iteration is `i`, then `j`, then `k`, with `k` varying fastest.
This detects both an `8x32x1`/`16x16x1` shape collision and a permutation of
otherwise identical points. It validates rectangular grid topology and array
order, but not that a third-party file used the same real-space lattice basis.
Missing, malformed, or disagreeing metadata raises a `ValueError` naming the
file, dtype/shape, and either the scalar value or first mismatching index; no
unbounded array representation is included in diagnostics. `wavevector_index`
semantically labels the third (`k`) axis of `green` in the FLEX layout.
Schema v1 also asserts the producer's orbital order and centered fermionic
order `iomega_n = (2*n + 1 - nfreq)*pi*T` for `n=0..nfreq-1`; these are
producer assertions, not independently reconstructable facts.
The boundary trusts a schema-v1 H-wave producer assertion: metadata cannot
detect a malicious or corrupt file that permutes only Green slices while
leaving canonical labels untouched. A negative test documents that limitation.

Strictness lives in a bond-only `_load_bond_green_npz` wrapper. The generic
`_load_green_npz` API and its existing callers are unchanged.

## Producer Changes

`FLEX.save_results` will add the following additive keys to `green.npz`:

- `green_schema_version=np.asarray(1, dtype="<i8")`
- `temperature=np.asarray(self.T, dtype="<f8")`
- `cell_shape=np.asarray(self.lattice.shape, dtype="<i8")`

`wavevector_index` is already written by FLEX and becomes mandatory at the
bond boundary. Existing numerical arrays and layouts remain unchanged, but
exact-key-set NPZ consumers will observe the three additive keys; this is an
intentional schema evolution. The committed Onari fixtures and generator will
write all required fields. `Lattice._init_lattice` pads one- and
two-dimensional inputs and guarantees that `self.lattice.shape` is always the
three-tuple `(Nx, Ny, Nz)`, including `(Nx, Ny, 1)` for a 2-D model and
`(Nx, 1, 1)` for a 1-D model, using the same axis convention consumed by the
bond entry point and `_klist`. Old metadata-free files are rejected with an
error instructing users to regenerate them with the updated FLEX writer (or,
for the bundled data, the fixture generator). There is no metadata-annotation
shortcut because temperature and ordering cannot be reconstructed safely.
The writer also canonicalises `wavevector_index` to little-endian int64 and
the Green payload with
`np.ascontiguousarray(green, dtype=np.dtype("<c16"))` before `np.savez`; this
prevents a consumer-side byteswap or contiguity allocation. Unknown
`green_schema_version` values are rejected rather than guessed.
FLEX currently produces C-contiguous complex128 Green arrays; a producer test
locks that invariant, so canonicalisation does not change numerical values,
dtype, or element count. The original `self.T` is validated as a finite
positive real scalar before conversion and serialization.

## Loader and Data Flow

The bond entry point already knows the authoritative `T`, `Nx`, `Ny`, and
`Nz`. It passes them to the Green header/metadata inspection before resource
preflight and to the full loader after allocation.

The bond wrapper owns one `_ValidatedBondGreenArchive` context for inspection
and full loading. It opens the path once, records `fstat`, and uses that file
descriptor through conversion; it does not reopen by pathname. Before reading
payloads it enumerates the ZIP central directory, with at most 128 members and
16 KiB of member-name text, and rejects directory paths, duplicate member
names, and duplicate required basenames. Every required key resolves to
exactly one root member (`<key>.npy`). At least one of `temperature.npy` and
`T.npy` is required, with at most one of each; a `T`-only fixture is accepted
for compatibility, while canonical plus alias triggers the three comparisons
defined above.
These sanity limits are applied after Python's ZIP reader parses the central
directory. ZIP objects/comments/extras are interpreter metadata excluded from
`bond_memory_cap_gb`; this loader is for trusted local scientific inputs, not
an adversarial archive security boundary. NumPy's forced-ZIP64 local-member
framing is accepted, as are ZIP64 central-directory sizes, after converting
all 64-bit sizes/offsets to checked Python integers and applying the same
member-count, header, shape, exact-size, and cap validation. This preserves
round-trip compatibility with `np.savez`; ZIP64 does not bypass any bound.

All members use `allow_pickle=False`. A bounded NPY parser rejects headers
larger than 4096 bytes and checks shape, C order, dtype, itemsize, and ZIP
uncompressed payload size before allocation:

- schema version: shape `()`, little-endian int64;
- temperature / optional `T`: shape `()`, little-endian float64;
- cell shape: shape `(3,)`, little-endian int64;
- wavevector index: shape `(expected_nvol, 3)`, little-endian int64;
- green: `(1, nfreq, expected_nvol, expected_norb, expected_norb)`, C-order,
  little-endian complex128, with positive even `nfreq`.

`wavevector_index` is stream-compared against `_klist` in 61,440-byte chunks
(2,560 complete 24-byte rows). Each read requests
`24 * min(2560, remaining_rows)` bytes, so the final partial chunk is exact
using a `read_exact` loop that accumulates valid short reads until the request
is satisfied or EOF occurs; EOF-before-count or any trailing byte fails.
Comparison begins at the parsed
NPY `data_offset`, after magic/version/header bytes. For every member,
`ZipInfo.file_size == data_offset + itemsize * math.prod(shape)` is required.
The full table is never materialised.
Inspection owns one 61,440-byte input buffer and one 61,440-byte
expected-value buffer, plus the at-most 4096-byte header
and a 4096-byte allowance for scalar metadata.
`inspection_bytes = 131_072` is therefore an explicit phase in the cap
estimate. Python object and ZIP decompressor internals are outside this
application-array cap, just as BLAS internals are. Stream validation consumes
the complete member and verifies the ZIP CRC. The archive's `(st_dev, st_ino,
st_size, st_mtime_ns)` snapshot is checked before and after inspection and
again after the Green read; replacement by pathname cannot affect the open
descriptor, while detected in-place mutation fails. This is ordinary
concurrent-change detection, not a cryptographic integrity proof.
Only root members with printable ASCII names and no slash, backslash, NUL,
encryption, or symlink external attributes are accepted. Compression is
limited to ZIP_STORED and ZIP_DEFLATED. The header-derived uncompressed size
is what feeds the cap, so highly compressible but valid scientific arrays do
not need an arbitrary ratio exception.

NPY validation reads the raw header `descr`, then compares its normalized
`np.dtype` to the required little-endian dtype. Native `=` on a little-endian
host is equivalent and zero-copy; serialized big-endian payloads are rejected
because accepting them would require an unbudgeted byteswap copy.
Schema v1 supports NPY header versions 1.0, 2.0, and 3.0 using their specified
header-length encodings; other versions, non-dict headers, extra/missing dict
fields, object descriptors, and malformed shape/order values are rejected.
Bond schema v1 execution is restricted to little-endian hosts.

The expected wavevector rows are generated arithmetically for only the current
chunk from the three centered/rolled `_klist` formulas; the checker never
calls the full-table constructor. Unit tests prove chunked equivalence to
`RPA._init_wavevec` for representative 1-D, 2-D, and 3-D shapes. Safe extra
root members such as existing frequency metadata and `wavevector_unit` are
ignored after the archive-wide bounds and ZIP checks.
Normatively, `_klist(n) = roll(arange(n) - n//2, -n//2)`: examples are
`n=3 -> [0, 1, -1]` and `n=4 -> [0, 1, -2, -1]`.

After the cap decision, the same validated member is materialised as
`green_raw`. Conversion to the existing `sc.py` layout
`(norb, norb, Nx, Ny, Nz, nfreq)` requires a C-order `.copy()`, so source and
destination coexist. The load/conversion phase is exactly
`2 * green_bytes`; `green_raw` is deleted before bubble construction. No
byteswap or dtype/order normalisation is permitted in the loader. All metadata
and CRC validation completes and its stream buffers are released before
`green_raw` is materialised. Defense in depth after materialisation is limited
to checking `green_raw.shape`, dtype, and C-contiguity, which allocates no
numerical buffer. Reading `green_raw` to EOF verifies its CRC again. The
conversion sequence is exactly
`green_raw[0].reshape(nfreq, Nx, Ny, Nz, norb, norb)`
`.transpose(4, 5, 1, 2, 3, 0).copy()`: reshape and transpose are views and the
final copy is the sole destination allocation.

The file's positive even Matsubara count continues to override configured
`Nmat`; this behaviour is unchanged.
The header yields `nfreq` first; `_bond_memory_estimate` uses this file value,
not configured `Nmat`, for every later phase.

## Memory Accounting

The resource estimate will gain a static analytical `precondition_bytes`
component determined from:

- `vec_size = norb**2 * Nx * Ny * Nz`;
- the effective `bond_precondition_dense_limit`;
- complex128 item size and the explicitly documented live buffers below.

When `vec_size` exceeds the dense limit, the estimate accounts only for the
random-probe vectors. The dense branch is selected exactly when
`vec_size <= bond_precondition_dense_limit`.
The limit is a count of complex vector elements (the square operator
dimension), not bytes or spatial volume, and zero is allowed to force probe
mode.

The implementation will make the allocation lifetime explicit. Define
`matrix_bytes = 16 * vec_size**2` and
`vector_bytes = 16 * vec_size`:

- The dense helper allocates six named matrix slots once: `K`, `M`, `N`,
  `left`, `scratch_conj`, and `scratch_delta`. K columns use one reusable `e`
  and one returned matvec vector. Metric application is refactored to
  `_apply_metric_into(..., out=...)`: diagonal metrics use `np.multiply`,
  block metrics use `np.einsum(..., out=...)`, and identity uses `np.copyto`;
  none returns another matrix.
- `_refer_to_ktilde_into` writes `left = S M`, conjugates into
  `scratch_conj`, writes the second metric application directly into `N`,
  and conjugates `N` in place. Residuals use
  `np.conjugate(A.T, out=scratch_conj)` and
  `np.subtract(A, scratch_conj, out=scratch_delta)` before
  `np.linalg.norm(scratch_delta)`.
- After scalar diagnostics are recorded, all six full-helper slots are
  released. Each part invokes the same helper, so it never overlaps the full
  matrices or another part.

Only one named-helper phase is live at a time. Its direct numerical arrays are
`6 * matrix_bytes + 13 * vector_bytes`. The helper
allocates reusable `e`, returned matvec output, `a`, `b`, `u`, `v`, `Ku`,
`Kv`, `Wu`, `Wv`, two float64 RNG buffers whose combined bytes equal one
complex vector, and two complex expression/result scratch vectors. Random
generation uses the generator's `out=` API, conjugation/multiplication uses
`out=`, and old matvec outputs are released before replacement. At no program
point do more than thirteen complex-vector equivalents coexist. The exact
named-buffer count is therefore `6 * matrix_bytes + 13 * vector_bytes`.

The cap is explicitly a conservative estimate, not an exact NumPy-allocation
or process-RSS bound. To cover unnamed NumPy contraction/reduction
temporaries, `precondition_bytes` applies a 2x safety factor to the direct
helper count:

- dense: `12 * matrix_bytes + 26 * vector_bytes`;
- probe: `26 * vector_bytes`.

This static factor is analytical and intentionally exceeds the measured
current high-water mark; measurement does not define the formula. FFT/BLAS
library-private plans and allocator arenas remain outside the option's stated
scope.

The dense full check and each part check are separate helper phases with
explicit ownership transfer. Diagnostics are reduced to Python scalars and
full-phase `K`, `M`, and `N` are deleted before a part phase starts. `K`, `M`,
`N`, and their part equivalents are newly allocated check workspace and never
aliases of retained operator inputs.
All three `LinearOperator` objects (`full`, `pp`, and `fl`) have the identical
shape `(vec_size, vec_size)`, where
`vec_size = norb**2 * Nx * Ny * Nz`; bond channels are factorized internal
workspace and do not enlarge the input/output vector. Thus every named dense
slot is exactly `vec_size` squared. `check_hermitian_preconditions` selects
dense versus probe once from this shared dimension. Parts are checked only
inside `if parts and method == "dense"`; they cannot independently select a
dense branch after the full operator selected probes.
Skipping part-wise diagnostics in probe mode is intentional: full-kernel
Hermiticity is the hard eigenvalue precondition, while pp/fl part checks only
qualify attribution. `attribute_lambda` still reports each part's imaginary
quotient in probe mode rather than claiming independently proven Hermiticity.

The top-level estimate is phase based, using the maximum of:

1. archive inspection (`inspection_bytes`);
2. FLEX `green_raw` plus converted `green_kw` (`2 * green_bytes`);
3. `green_kw`, `chi_bar`, and bubble work buffers;
4. retained `green_kw`/`chi_bar`, q-resolved `S_bond`, `C_bond`, `chi_s`,
   `chi_c`, fluctuation/kernel FFT arrays, and bare `Vpp_s`/`Vpp_t` plus
   vertex temporaries;
5. those operator-closure inputs plus pair weight and
   `operator_matvec_bytes`;
6. the phase-5 retained inputs plus `precondition_bytes`.

Here `B = int(bond_set.n_channels)`.
The named operator workspace `(6*B + 4) * vector_bytes` is additional to the
thirteen direct helper vectors. It covers simultaneous `X`; the fluctuation
path's `Z`, transform input/output, `W_r`, `W_k`, and result; and, for the full
operator, the retained fluctuation result plus instantaneous
`A_coef`/`Bcoef`/result and addition output. This workspace overlaps K-column
construction and is therefore present in phase 6, not hidden inside
`precondition_bytes`.
The reported/budgeted value applies the same 2x unnamed-temporary allowance:
`operator_matvec_bytes = 2 * (6*B + 4) * vector_bytes`.

Each term lists its live arrays in `_bond_memory_estimate`; mutually exclusive
phase maxima are not summed. `bond_memory_cap_gb` continues to mean decimal
gigabytes (`1 GB = 1_000_000_000 bytes`).
All dimensions and byte products are converted to Python `int`, checked
positive and against `sys.maxsize`, before multiplication or allocation;
NumPy fixed-width arithmetic is never used for sizing.

`_bond_resource_preflight` receives the effective precondition options so the
estimate uses the same dense-limit decision as runtime. Its error message and
returned breakdown include `precondition_bytes`.

## Error Handling

All metadata-provenance failures occur before the Green array or bond vertex
is materialised. Payload truncation/CRC failure may surface while
`green_raw` is materialised, before conversion or operator construction.
Messages distinguish:

- missing temperature metadata;
- invalid or mismatched temperature;
- missing grid metadata;
- mismatched grid shape;
- invalid or inconsistently ordered `wavevector_index`.

Memory-cap failures continue to use `ValueError`, now reporting inspection,
operator-matvec, and dense/probe precondition estimates explicitly. The option
is a conservative application-owned numerical-array estimate, not a hard
bound on NumPy allocation or process RSS;
Python, ZIP, allocator, FFT, and BLAS implementation-private workspaces may
raise RSS above it.

## Testing

Tests follow RED-GREEN-REFACTOR:

1. A `T=0.02`, `16x16x1` fixture must fail when loaded for another temperature.
2. The same fixture must fail when loaded as `8x32x1`.
3. Missing temperature or grid metadata must fail on the bond path.
4. Matching metadata must preserve the existing milestone eigenvalue.
5. Newly written FLEX Green files must contain canonical provenance metadata.
6. Analytical unit tests cover `dense_limit-1`, `dense_limit`, and
   `dense_limit+1`, plus
   tolerance boundary, NaN/infinity, scalar shape, endian/dtype, oversized
   header, member-count/name bounds, duplicate ZIP member, CRC, shape,
    duplicate-index, and permuted metadata. Producer-to-loader round trips run
    on every supported NumPy/Python environment and exercise NumPy's ZIP64
    member framing.
7. A measured dense-precondition peak must fit within the documented static
   safety budget. Named buffer-count tests are deterministic;
   the integration measurement uses `tracemalloc` after allocator warm-up,
   subtracts a no-op baseline, and does not claim to observe native BLAS
   memory. A separate deterministic test instruments the six named matrix
   slots, thirteen vector-equivalent slots, and operator-matvec workspace;
   the 2x safety factor remains explicit rather than being reverse-engineered
   from that measurement.
8. A cap between the old estimate and the corrected estimate must be refused
   before operator construction.
9. Existing non-bond loaders and legacy numerical output remain unchanged.
10. A sentinel Green tensor encoding frequency, k index, and orbital indices
    verifies the exact reshape/transpose mapping element by element.
11. Archive tests cover unknown schema/NPY versions, canonical/alias mismatch
    combinations, non-root/encrypted/symlink members, ZIP64 boundaries,
    configured-Nmat
    override, size overflow, truncation, and mutation between passes.
12. An end-to-end dense test measures the phase maximum while retained
    operator inputs and matvec workspace are live, not only the isolated
    precondition helper.

The focused bond tests, spectral-shift tests, dynamic tests, full pytest suite,
`unittest discover`, lint, and `git diff --check` are run before publishing.
