scf_status¶

自己無撞着(SCF)計算の収束状態 (収束したか、最後の残差、収束判定値、ステップ数) を出力します。 このファイルはデフォルトで出力ディレクトリにscf_status.datとして、他のどの結果ファイルよりも先に出力されます。 ファイル名はfile.outputセクションのキーワードscf_statusで指定でき、scf_status = ""とすると出力されません。

以下にファイル例を記載します。

format_version = 1
solver = UHFk
converged = true
residual = 8.537948717029953e-16
eps = 1e-12
iterations = 1
iteration_max = 1000
residual_definition = two_frobenius_over_size:uhfk_all_r
note =

ファイル形式¶

各行はちょうどkey = valueと改行からなり、=の両側に空白を1つずつ置き、それ以外の空白は入りません。 キーは常に以下の順に並びます。値が空のときはkey =の後に空白1つと改行だけが続きます (通常の計算のnote =など)。

  • format_version = 1

  • solver = UHFk

  • converged = [converged]

  • residual = [residual]

  • eps = [eps]

  • iterations = [iterations]

  • iteration_max = [iteration_max]

  • residual_definition = two_frobenius_over_size:uhfk_all_r

  • note = [note]

パラメータ¶

  • [converged]

    形式 : trueまたはfalse

    説明 : 最後の残差がeps未満、すなわち収束してループが終了した場合にtrueとなります。

  • [residual]

    形式 : float型 (Pythonのreprによる全桁表示) またはnan

    説明 : 最後に完了したステップの残差

    (4.1)¶\[R = \frac{2\,\lVert G_{\rm new} - G_{\rm old} \rVert_F}{\mathrm{size}(G)}\]

    です。ここで\(G_{\rm old}\)はステップ開始時のグリーン関数、\(G_{\rm new}\)はそのステップで計算されたもの (混合前)、\(\lVert\cdot\rVert_F\)はFrobeniusノルム、\(\mathrm{size}(G)\)は\(G\)の要素数です。 UHFkでは\(G\)は形状(nvol, ns, norb, ns, norb)の配列で、セル内のすべての並進ベクトル\(r\)とすべてのスピン・軌道の組を含みます (スピン軌道モードではns = 1で、norbはスピン軌道の数)。 UHFrは同じ式を\(2N \times 2N\)の行列全体に適用します。

    \(R\)はノルムを要素数で割っているため、要素ごとの変化が同程度であれば系が大きいほど小さくなります (Frobeniusノルムは要素数の平方根でしか増えないため)。 したがって残差とEPSは、\(G\)の配列の大きさが等しい計算どうしでのみ比較できます。

    ステップを1回も行わなかった場合、または最後のステップの残差が有限でなかった場合 ([note]を参照) はnanです。

  • [eps]

    形式 : float型

    説明 : 収束判定値\(10^{-\mathrm{EPS}}\)(mode.paramのEPS)。

  • [iterations]

    形式 : int型

    説明 : 完了したSCFステップの数 (収束したステップを含む)。print_checkファイルを指定した場合はその行数と一致します。

  • [iteration_max]

    形式 : int型

    説明 : mode.paramのIterationMax。

  • [note]

    形式 : 文字列 (空の場合あり)

    説明 : 通常の計算では空です。それ以外では次のいずれかです。

    • no SCF step performed: IterationMax = 0の場合。

    • residual not finite after step <n>: 最後に完了したステップ<n>の残差がNaNまたは無限大だった場合。このときresidualはnan、convergedはfalseです。

    • IterationMax <value> treated as 0: 負のIterationMax(trustme_interaction_rangeでパラメータチェックを緩めた場合にのみ受け付けられます) はステップを行わず、iteration_max = 0として出力されます。

不変条件¶

  • epsは有限の正の値です。

  • \(0 \le\)iterations\(\le\)iteration_maxです。

  • iterations> 0 のとき、residualは有限の非負の値か、または注記residual not finite after step <n>を伴うnanです。

  • converged = trueのとき、iterations> 0 かつresidual< epsです。

  • iterations = 0のとき、converged = falseかつresidual = nanです。

SCFステップを行わない場合¶

IterationMax = 0の場合はステップを行いません。WARNINGが1つ出力され、結果ファイルはscf_status.datのみが出力されます (iterations = 0、converged = false、residual = nan、注記no SCF step performed)。 energy、eigen、greenなどの他の出力は行われません。 print_checkファイルを指定している場合は空のファイルが作成されます。 scf_status = ""の場合は結果ファイルが1つも出力されず、WARNINGにもそのように記されます。 以前のバージョンでは、この場合はエラーで停止していました。

logセクションのprint_check(各ステップのステップ番号、残差、エネルギー、NCond、Sz) はこれまでどおり利用できます。

注釈

キー名scf_statusは、file.outputの他のキーと同様に完全一致で照合されます (SCF_Statusは別のキーとして扱われます)。 値は文字列でなければならず、またステータスファイルはその計算の他の結果ファイルやprint_checkファイルと同じファイルであってはなりません。 ファイルは実際に書かれる形で比較されます。すなわち、パスを解決し (./check.datはcheck.datと同じ)、どのプラットフォームでも大文字・小文字を区別せず (macOSやWindowsの大文字・小文字を区別しないファイルシステムと同様にEnergy.datはenergy.datと同じ)、NumPyが付ける.npz(UHFkのgreen、eigen、rpa)、デフォルト (UHFkのgreen = "green")、生成される名前 (UHFrのsz-free_/spin-up_/spin-down_付きのeigenファイルとsz-free_/Sz0_付きのfijファイル、UHFkのexport_hamiltonianのファイル) を含めて比較します。 hwave(hwave.qlms.run) から実行した場合、そのような値 (例えばfalse、0、UHFkでgreenを指定しないときの"green.npz") は計算開始前にエラーとなります。 ソルバーのクラスを直接呼び出すプログラムでも、save_resultsの最初、ファイルを書く前に同じエラーとなります。 この確認には、その設定では実際には出力されないものも含め、ソルバーが書きうるすべてのファイル名が使われます。
