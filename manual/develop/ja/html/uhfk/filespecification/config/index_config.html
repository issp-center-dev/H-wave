4.2.1. 環境設定ファイル¶

このファイルでは、TOML形式でH-waveに関する環境を設定します。 本ファイルは以下の3つのセクションから構成されます。

  1. modeセクション: 計算モードに関する設定を指定するセクション。

  2. logセクション: 標準出力に関する設定を指定するセクション。

  3. fileセクション: 入出力ファイルのパスなどを設定するセクションで、input , outputのサブセクションから構成される。

以下、ファイル例を記載します。

[log]
  print_level = 1
  print_step = 10
[mode]
  mode = "UHFk"
[mode.param]
  # 2Sz = 0
  Ncond = 16
  IterationMax = 1000
  EPS = 8
  Mix = 0.5
  RndSeed = 123456789
  # ene_cutoff = 1.0e+2
  T = 0.0
  CellShape = [ 4, 4, 1 ]
  SubShape = [ 2, 2, 1 ]
[file]
[file.input]
  path_to_input = ""
  # initial = "green_init.dat.npz"
[file.input.interaction]
  path_to_input = "./"
  Geometry = "geom.dat"
  Transfer = "transfer.dat"
  CoulombInter = "coulombinter.dat"
[file.output]
  path_to_output = "output"
  energy = "energy.dat"
  eigen = "eigen"
  green = "green"

ファイル形式¶

TOML形式

パラメータ¶

modeセクション¶

modeテーブル自体に書くキーはmode、calc_scheme、calc_type、 enable_spin_orbital、flag_fock（選んだソルバーが対応しているもの。以下を参照） だけで、名前は大文字・小文字も含めてこのとおりに書きます。それ以外のソルバーの パラメータはmode.paramに書きます。modeにそれ以外のキーや大文字・小文字の 異なるキーがある場合、またmode.paramにこれらのキー（大文字・小文字を問わない）や 入れ子のparamテーブルがある場合、hwaveはエラーで停止します。また、計算の 最後に、その計算で読まれなかったmode.paramのキー（綴りの誤りや、現在の設定では 効かないパラメータ）を警告します。

  • mode

    形式 : string型

    説明 : 計算モードを指定します。実波数空間UHFを利用する場合には、UHFk (波数空間版)を記載します。

  • flag_fock

    形式 : bool型 (デフォルトはtrue )

    説明 : trueの場合にはFock項を考慮し、falseの場合にはHartree項のみ取り扱います。

  • enable_spin_orbital

    形式 : bool型 (デフォルトは false。"true"のように解釈できる文字列は 警告付きで受け付け、解釈できない値はエラーになります)

    説明 : スピン軌道相互作用を有効にします。Transfer項の軌道のインデックスはスピン自由度を含む形に解釈されます。インデックスの対応は、軌道\(\alpha\) (0 から\(N_\text{orb}-1\)) とスピン\(s\) (0: up, 1: down) に対して\(2\alpha + s\)となります（スピンを内側に並べたインターリーブ順）。相互作用項（CoulombIntra, CoulombInter, Coulomb, Hund, Ising, Exchange, PairLift, PairHop）もスピン軌道モードで利用でき、仮想スピン分解を介して取り扱われます。

mode.paramセクション¶

mode.paramセクションでは計算用のパラメータを指定します。

  • CellShape

    形式 : int array型

    説明 : box の形状 Lx, Ly, Lz を指定します。

  • SubShape

    形式 : int array型 (デフォルトは[ Lx, Ly, Lz ])

    説明 : 副格子の形状 Bx, By, Bz を指定します。

  • T

    形式 : float型 (デフォルトは0)

    説明 : 温度を指定します。0以上の値を指定してください。

  • Ncond

    形式 : int型

    説明 : 伝導電子の数を指定します。1以上の値を指定してください。

  • filling

    形式 : float型

    説明 : 伝導電子の状態数に対する占有率を指定します。0以上1以下の値を指定してください。Ncondと同時に指定されている場合はエラーで終了します。

  • Ncond_round_mode

    形式 : str型 (デフォルトは"strict")

    説明 : fillingから計算される伝導電子数を整数値に丸める方法を指定します。以下のいずれかの値をとります。

    • as-is : 丸めを行いません。(戻り値は float型です)

    • round-up : 小数点以下を切り上げます。

    • round-down : 小数点以下を切り捨てます。

    • round-off : 小数点以下を四捨五入します。

    • round : 小数点以下をround関数で丸めます。0.5 は 0 に丸められるので注意。

    • strict : 整数でない場合はエラーで終了します。

    • exact : 整数でない場合は warning を表示し、roundで丸めた整数値を返します。

  • 2Sz

    形式 : int型、または文字列"free"(デフォルトは指定なしで、"free"と同じ)

    説明 : スピンの\(z\)成分を固定する場合に、全スピンの\(z\)成分の 2 倍の値を指定します。 このときアップとダウンのスピンセクタを(Ncond + 2Sz)/2個と(Ncond - 2Sz)/2個の電子で別々に解き、平均場ハミルトニアンのスピン非対角成分は使いません。 何も指定しない場合、または"free"を指定した場合は、スピン空間を分けずに計算します。 2Szの偶奇はNcondと一致している必要があり、enable_spin_orbital = trueとは併用できません。 固定した2Szでは、Transferのスピン反転の一体項はエラーになります。 \(S_z\)を保存しない相互作用項 (PairLift) はスピン非対角成分にしか寄与しないため、固定した2Szでは無視されます。 計算はそのまま続き、その項の名前を挙げた警告を 1 回ログに出します。これらの項を含めるには2Szを指定しないか、2Sz = "free"を指定してください。

  • IterationMax

    形式 : int型 (デフォルトは20000)

    説明 : 反復回数の上限を指定します。0以上の値を指定してください。

  • EPS

    形式 : int型 (デフォルトは6)

    説明 : 収束条件を指定します。一つ前のステップのグリーン関数との差のノルムが\(10^{\rm -EPS}\)以下になった場合に収束したと判定します。 残差は\(R = \sum_{i, j}^{N} \sqrt{ \left| G_{ij}^{\rm new} - G_{ij}^{\rm old} \right|^2} / 2N^2\)で定義されます。 0以上の値を指定してください。

  • Mix

    形式 : float型 (デフォルトは0.5)

    説明 : Green関数の更新時に、古い値と新しく得られた値を混ぜる(simple-mixing)割合\(\alpha\)を指定します。 0以上から1以下の実数で指定してください。1にすると古い値は使われません。 simple-mixingについてはアルゴリズムの章をご覧ください。

  • RndSeed

    形式 : int型 (デフォルトは1234)

    説明 : 乱数のシード(種)を指定します。

  • ene_cutoff

    形式 : float型 (デフォルトは100.0)

    説明 : Fermi分布関数を計算する際に overflow を避けるためのカットオフを指定します。

  • strict_hermite

    形式 : bool型 (デフォルトは false)

    説明 : 相互作用定義ファイルの読み込み時に Hermiticity を厳密にチェックします。true の場合、hermite_tolerance以上のズレが見つかったときはエラーで終了します。false の場合は warning を表示して実行を継続します。

  • hermite_tolerance

    形式 : float型 (デフォルトは\(10^{-8}\) )

    説明 : Hermiticity の許容値\(|t_{ij} - t_{ji}^*| < \varepsilon\)を指定します。

  • trustme_interaction_range

    形式 : bool型 (デフォルトは false)

    説明 : ホッピングや相互作用の距離がCellShapeの半分以内におさまっているかのチェックを緩和します。 true の場合、warning を表示して実行を継続し、 false の場合、エラー終了します。 true のとき、CellShapeの外にある並進ベクトルは成分ごとにCellShapeを法として セル内に折り返し、同じベクトルに折り返された項は足し合わせます。CellShapeの k メッシュ上では、 折り返す前の表と同じハミルトニアンになります。各行の種類は書かれたベクトルのまま判定するので、 たとえば折り返すとゼロになるサイト間の行は、周期的な像とのサイト間相互作用のまま扱います。

logセクション¶

  • print_level

    形式 : int型 (デフォルトは1)

    説明 : 標準出力のレベルを指定します。1にすると詳細な情報が出力されます。

  • print_step

    形式 : int型 (デフォルトは1)

    説明 : 反復計算の途中に計算ログを標準出力に書き出す間隔を指定します。1以上の値を指定してください。

  • print_check

    形式 : str型 (デフォルトはNone)

    説明 : 反復計算の途中に計算ログをファイルに書き出す場合、出力先ファイル名を指定します。無指定のときは出力しません。

fileセクション¶

inputとoutputのサブセクションからなります。 前者は入力ファイルに関する情報(格納場所やファイル名の指定など)、後者は出力ファイルに関する情報(格納場所など)について指定します。 以下、順に説明します。

file.inputセクション¶

  • path_to_input

    形式 : str型 (デフォルトは "")

    説明 : 入力ファイルの格納されているディレクトリを指定します。

  • initial

    形式 : str型

    説明 : 初期状態の一体グリーン関数データを格納したファイルの名前を指定します。 ファイルは NumPy binary 形式です。 file.outputのgreenの出力ファイル形式に対応しています。

  • initial_mode

    形式 : str型

    説明 : 初期状態の一体グリーン関数データが指定されていない場合、初期値をどのように取るかを指定します。以下のいずれかの値を取ります。

    zero: 初期値を 0 に設定します。(デフォルト)

    oneまたはunity: 初期値を\(G_{\alpha\sigma,\beta\sigma^\prime}(\vec{r}) = \delta_{\vec{r},0}\delta_{\alpha\beta}\delta_{\sigma\sigma^\prime}\)で与えます。

    random: 初期値を乱数で与えます。

  • geometry_uhf

    形式 : str型

    説明 : 実空間のサイト表示での幾何情報ファイルの名前を指定します。形式は mVMC の StdFace が書き出すgeometry.datと同じで、 格子ベクトル 3 行 (1 行に 1 ベクトル)、境界位相 3 成分の行 (読み込みますが使いません。UHFk の境界条件は常に周期境界です)、 スーパーセルのベクトル 3 行、そのあとにサイトごとの整数のx y z orbitalの行が並びます。 サイトの行には 0 から番号を付け、その番号がinitial_uhf、onebodyg_uhf、onebodygのサイト番号i、jになります。 x y zはCellShape内のセル座標 (\(0 \le x < L_x\)など。SubShapeを使う場合も同じ)、orbitalは 0 から数えた軌道番号です。 initial_uhfとfile.outputのonebodygで必要で、それ以外では省略できます。

  • initial_uhf

    形式 : str型

    説明 : 実空間のサイト表示での初期状態の一体グリーン関数データを格納したファイルの名前を指定します。 各行は 1 要素i s j t Re Im(\(\langle c^\dagger_{is} c_{jt}\rangle\)のサイトとスピン) で、ヘッダはありません。 i、jはgeometry_uhfのサイト番号、s、tはスピン番号で 0 (アップ) または 1 (ダウン) です。 これはfile.outputのonebodygが書き出す形式で、その出力をそのまま読み戻せます。 UHFr の出力green(ヘッダなし) とinitial(5 行ヘッダ付き) も同じ行の形式で、 先頭行が=で始まるファイルは 5 行のヘッダを読み飛ばして読み込みます。 セル\(\vec{R}_i\)、軌道\(a\)のサイトiとセル\(\vec{R}_j\)、軌道\(b\)のサイトjの行は、 green.npzの要素\(G_{sa,tb}(\vec{R}_i-\vec{R}_j)\)(変位はCellShapeを法として取ります) を与えます。 並進対称性により、サイトiがセル0 0 0にある行だけを使い、そのような行のない要素は 0 から始めます。 したがって完全な初期状態には、iがセル0 0 0にありjがすべてのサイトを走るすべての(i, s, j, t)が必要です。 それ以外の行は使わず、そのうち異なる(i, s, j, t)の数をログに INFO として 1 行で出力します。 同じ要素を与える行 (同じ(i, s, j, t)の繰り返しや、変位をCellShapeを法として取ると同じになる 2 つのサイトj) は、 最初の行と、複素数の値の差の絶対値で\(10^{-10}\)以内で一致している必要があります。 この許容誤差内で一致する行は受け付け (最後の行の値を使います)、値が異なる場合はその要素と 2 つの値を示すエラーで停止します。 同じ(i, s, j, t)の繰り返しは、ファイルの読み込み時に、使わない行も含めたすべての行について検査します。 file.inputのgeometry_uhfが必要です。initialと同時には指定できません。この入力にはSubShape = [1, 1, 1]が必要で、それ以外ではエラーで停止します。 副格子秩序をもつ状態は、代わりにinitial(green.npz) で与えてください。 initialもinitial_uhfも指定しない場合、初期値はinitial_modeに従います。

    注釈

    リリースと移行に関する注意: greenone.dat と initial_uhf。 onebodygは\(\langle c^\dagger_{\vec{R}_i a s} c_{\vec{R}_j b t}\rangle = G_{sa,tb}(\vec{R}_i-\vec{R}_j)\)を、 変位をgreen.npzと同じ順序 (z 方向優先) で参照して (通常はgreenone.datに) 書き出すようになり、initial_uhfも同じ規約で読み戻します。 以前は\(G(\vec{R}_j-\vec{R}_i)\)を x 方向優先の順序で読んでおり、SubShapeが[1, 1, 1]より大きい場合は 副格子の分解が失われていました (生成演算子のサイトをすべて最初の副格子のサイトとして扱っていました)。 SubShape = [1, 1, 1]では、2 つのサイトが同じセルにある要素は変わりません。それ以外の要素は、反転対称性のない状態 (複素数のホッピングなど) や 2 方向以上に広がったセルで値が変わることがあります。SubShapeが[1, 1, 1]より大きい場合は、他の副格子のサイトにある同じセル内の要素を含め、どの要素も変わりえます。 値は同じクラスタの UHFr と一致するようになりました。 以前のリリースでは NumPy 1.24 以降でgeometry_uhfの読み込みが失敗したため、サポート対象の NumPy ではonebodygもinitial_uhfも使えませんでした。 ファイルにはバージョンを識別する情報がありません。古いgreenone.datをinitial_uhfで再利用する前に、再生成してください。

  • onebodyg_uhf

    形式 : str型

    説明 : file.outputのonebodygで書き出す一体グリーン関数の要素の一覧 (mVMC / UHFr のgreenone.def形式: 読み飛ばされるヘッダ 5 行のあとに 1 要素 1 行のi s j t) を格納したファイルの名前を指定します。onebodygを指定する場合は必要で、使わない場合は省略できます。

file.input.interactionセクション¶

波数空間版UHFで、幾何情報や相互作用のタイプと定義ファイルとの対応付けを行います。

  • path_to_input

    形式 : str型

    説明 : 入力ファイルを格納するディレクトリを指定します。file.inputセクションのpath_to_inputとは独立に指定できます。

  • Geometry

    形式 : str型

    説明 : 幾何情報のファイル名を指定します。

  • Transfer, CoulombIntra, CoulombInter, Coulomb, Hund, Ising, Exchange, PairLift, PairHop

    形式 : str型

    説明 : 各相互作用の係数ファイル名を指定します。

file.outputセクション¶

  • path_to_output

    形式 : str型 (デフォルトは"output" )

    説明 : 出力ファイルを格納するディレクトリを指定します。

  • energy

    形式 : str型

    説明 : エネルギーを出力するファイル名を指定します。このキーワードがない場合には情報は出力されません。

  • eigen

    形式 : str型

    説明 : ハミルトニアンの固有値を出力するファイル名を指定します。このキーワードがない場合には情報は出力されません。

  • green

    形式 : str型 (デフォルトは"green" )

    説明 : 一体グリーン関数を出力するファイル名を指定します。空文字列""を指定した場合には情報は出力されません。

  • onebodyg

    形式 : str型

    説明 : file.inputのonebodyg_uhfに列挙した一体グリーン関数の要素を実空間のサイト表示 (1 行にi s j t Re Im、ヘッダなし) で出力する ファイル名を指定します。各行は\(\langle c^\dagger_{is} c_{jt}\rangle\)で、UHFr の出力greenと同じ量・同じ形式です。 SubShape = [1, 1, 1]の場合、このファイルはinitial_uhfで読み戻せます (移行に関する注意を参照)。 それより大きいSubShapeではgreenの出力をinitialで読み込んで再開してください。file.inputのgeometry_uhfとonebodyg_uhfが必要です。 SubShapeが[1, 1, 1]より大きい場合も、収束した状態の副格子分解を保って出力します。 このキーワードがない場合には情報は出力されません。

  • scf_status

    形式 : str型 (デフォルトは"scf_status.dat" )

    説明 : SCF計算の収束状態 (scf_status ) を出力するファイル名を指定します。デフォルトで出力され、空文字列""を指定した場合には出力されません。値は文字列でなければならず、その計算の他の結果ファイル (.npzの付加や生成される名前を含め、大文字・小文字を区別せずに比較した、実際に書かれるファイル) やprint_checkと同じファイルにはできません。キー名は完全一致で照合されます。

  • rpa

    形式 : str型

    説明 : UHF法で近似した相互作用項を含む一体項を出力するファイル名を指定します。出力ファイルは RPAの初期値としてtrans_modパラメータに指定して利用できます。このキーワードがない場合には情報は出力されません。
